# T05 - 두 AI 간 인수인계(Blind Test)

## 과제 개요

T05는 두 개의 서로 다른 AI 모델이 동일한 과제 조건 하에서 작업을 수행하고, 인수인계를 통해 과업을 완수하는 과정을 검증하는 실험입니다.

## 목표

1. **작업 사전 고정**: 기능 1개, 고정 검사 10개, AI별 공통 사용 상한(시간/요청·호출 수)을 작업 전 미리 정한다.
2. **AI A 수행 및 인수인계**: AI A가 정해진 상한 내에서 작업 후, 저장소와 인수인계 문서를 남기고 중단한다.
3. **일급 인수인계**: 첫 대화 없이도 다른 작업자가 실행 가능한 수준의 인수인계 문서를 작성한다.
4. **AI B 이어받기**: AI A와 다른 서비스/모델의 AI B가 저장소와 인수인계 문서만으로 작업을 이어받아 완성한다.
5. **블라인드 비교**: 모델명 대신 측정 결과(시간/요청·호출/오류/통과 수)로 비교한다.

## 폴더/파일 구조

| 파일 | 설명 |

| `index.html` | T04 검증 대시보드 (실패→복구 시나리오 검증용) |
| `HANDOFF.md` | AI A→AI B 인수인계 문서 (목표/현상태/실행명령/통과검사/남은문제/다음행동/건드리지말것) |

| `SUBMISSION.md` | 제출물 정리 |

## AI 구성

| 구분 | 서비스/모델 | 역할 |
|---|---|---|
| AI A | Glyph Cluster (스텔스 모델, 세부정보 미공개) | 작업 수행 및 인수인계 |
| AI B | Kilo (nvidia/nemotron-3.5-super-vl:free) | 인수인계 기반 이어받기 (AI A와 다른 서비스) |

## 인수인계 원칙

- AI B에는 **저장소 전체 + HANDOFF.md만** 제공 (AI A 대화 기록 미제공)
- 고정 검사 10개는 **삭제/완화/기대값 변경 금지**
- 공통 사용 상한 준수: 시간 30분 / 요청·호출 수 50회
- 작업 순서: `A 시작 → A 종료·인수인계 → B 시작 → B 완료`

## 검증 시나리오

T04 대시보드를 활용한 실패→복구 시나리오 검증:

1. **초기화** - "7일 데이터 초기화 (Reset)" 버튼으로 결정론적 7일 데이터 생성
2. **실패 적용** - 드롭다운에서 장애 선택 후 "선택한 실패 적용 (Stale 전환)" 클릭
3. **복구 실행** - "T04-RECOVER-D2 실행 (복구)" 클릭
4. **대조 검증** - "원자료 · 저장값 · 화면값 대조"에서 3계층 일치 확인
